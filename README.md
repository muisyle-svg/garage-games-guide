# Garage Games event guide

A static, mobile-first website for the Garage Games event guidelines. Visitors need no account; the site works offline after the first visit.

Event text lives in `content/`. The website code lives in `src/` and `build.mjs`. You can edit events without touching code.

## Editing events

Each event is one Markdown file in `content/events/`. The file name becomes the web address: `wall-d.md` is served at `/events/wall-d/`.

```markdown
---
title: 'Wall-D'
order: 4               # position on the homepage
points: 100
grace_period: 20       # seconds before points start dropping
points_per_second: 2   # points lost each second after the grace period
finish: auto           # button = press again to stop, auto = time recorded automatically, none = no finish
image: wall-d.svg      # file in content/images/
---

## Objective
## Setup
## Gameplay
## Additional Guidelines and Clarifications
```

- Use only the headings you have text for; empty sections are left out.
- Scoring is shown as badges under the title, built from `points`, `grace_period` (stopwatch), `points_per_second` (falling arrow) and `finish: auto` (auto-stop badge). `points_label` adds a "per hit" badge (the bonus round uses this).
- Sections appear in this order: Objective, Gameplay, Additional Guidelines and Clarifications, then Setup/Reset (collapsed). Every page has an "Expand all" button.
- Optional fields: `subtitle` (small label above the title), `bonus: true` (shows a Bonus badge instead of points), `image_alt` (otherwise the objective is used).

The homepage steps, the "How it works" page and the general guidelines are in `content/site.md`.

## Animations

Each event has an animated SVG in `content/images/`. They are generated by `tools/animations.mjs`, which keeps one shared backdrop, palette and figure so they match. Edit a scene there, then run:

```
node tools/animations.mjs
```

Any image file (`.svg`, `.jpg`, `.png`, `.gif`) dropped into `content/images/` and named in an event's `image:` field works too.

## Photo slideshows

An event can show a captioned photo slideshow under its animation. Wall-D uses `slideshow: discs` in its front matter, which reads `content/slideshows/discs.md`: a `captions:` list paired in order with the photos in `content/images/discs/` (sorted by file name). To change it, swap photos in that folder and keep the captions list in the same order. The build warns if the counts differ.

## Live scores

The Scores page (`/scoreboard/`) shows the scorekeeper's leaderboards: the overall leaderboard (tap a name for that run's scorecard) and one leaderboard per event. Below the leaderboard, **Compare players** lets visitors pick up to four runs (shareable as `?compare=` with the last six characters of each run id) for event-by-event bars and a run race chart, and **How the events compare** ranks events hardest first. Events start at different points, so that board compares shares of each event's starting points, taken from the `points` front matter of the matching event file (matched by name). **On the course** plays the picked runs on `content/images/course.jpg`: each player walks between event bubbles following the start and finish times in `scores.json`. The bubble centers are listed in `COURSE` in `src/scoreboard.js`; update them if the course image changes. `src/scoreboard.js` draws it from `scores.json`, refreshing every 30 seconds.

The scorekeeper app uploads `scores.json` to the `live-scores` branch whenever the standings change (at most once a minute; setup is in the garage_games repo, `docs/PUBLIC-SCOREBOARD.md`). That branch's "Live scores updated" workflow sets off the deploy workflow, which builds `main` and copies the latest `scores.json` into the site. Nothing on `main` changes. Without a `scores.json` the page says scores appear once the games begin.

To preview the page locally, put a `scores.json` in `dist/` after building.

## Building and previewing

```
npm install
npm run build      # writes the site to dist/
npm run preview    # builds and serves it at http://localhost:3000
```

## Publishing

Every push to `main` rebuilds and publishes to GitHub Pages through `.github/workflows/pages.yml`. Cloudflare Pages works too: build command `npm run build`, output folder `dist`.
